# Job progress sharing

The mail button copies an email-ready message containing the progress link and its six-digit PIN, and briefly displays the PIN. Share that text only with the intended recipients. Copying the message enables access; opening a job or downloading the PNG does not. The viewer/editor can revoke a share, which replaces both the PIN and the link. An unlocked dashboard is a read-only view; reload and enter the PIN to see the latest data. A downloaded PNG stays as it was when downloaded and cannot be revoked.

The unlocked view includes the job title and stage, overall workflow score, linked task/deliverable names and stages, and the saved client delivery URL when valid. The delivery provider still controls access to its destination. Attachments are private until a production user marks a file **Share with client**. The snapshot returns only shared file metadata; each file click rechecks the PIN and sharing flag before generating a short-lived private storage link. Supported browser formats can be opened; all shared attachments can be downloaded. Unsharing prevents new file links but does not recall downloads or already-issued signed links. Internal notes, briefs, unshared files, contacts, schedules, costs and CRM links are not exposed. The PNG only contains the progress summary and stage totals.

Production team members and CRM admins can manage links for jobs they can access under their own RLS-bound session. Marketing-only accounts cannot issue external links or download share snapshots. PINs are service-only, not returned in job records, offline caches or ClickUp payloads. The link token travels in the browser URL fragment and is sent with the PIN only in a same-origin POST body; the dashboard has no telemetry, referrer or indexing. No session cookie is required and no unlocked data is cached by the app. Rate limiting is serialized in Postgres per link (five failed attempts in a fifteen-minute window). The generic link prompt exposes no job information.

The additive migration assigns a unique PIN to existing and newly inserted jobs without changing the jobs or enabling links. Archive retires an active token and unarchive does not restore it. Rollback the application deployment if needed; leave the isolated table in place unless credential removal is explicitly requested. The SQL verification fixture is for isolated Postgres, not for inserting test jobs in production.

The dedicated production address is `https://autopac-progress.vercel.app/job-progress`. The app serves only the progress page, PIN and file-access submissions, and required assets on that hostname. Set `NEXT_PUBLIC_JOB_PROGRESS_VERCEL_LINKS=1` on Vercel Production only after the hostname is verified and the route guard is live. This changes only the URL copied for a share; it does not rotate PINs or tokens. The previous website address remains a valid route for previously sent links.
